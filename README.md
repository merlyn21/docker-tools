# dockview

Терминальный UI для просмотра Docker-контейнеров и образов.

```
╭─ dockview ──────────────────────────────────────────────────────────────────╮
││  Containers    Images        ◂ ▸ switch tab                                 │
│╭ items ──────────────────────╮╭ details ──────────────────────────────────── ╮
││▶ ● web     nginx            ││ web                                          │
││  ○ db      postgres         ││ State    running                             │
││  ◆ node:21          1.1GB   ││ Image    nginx:latest                        │
││  ◆ postgres:16      438MB   ││ Size     1.03 GB                             │
││  ...                        ││ ...                                          │
│╰─────────────────────────────╯╰──────────────────────────────────────────────╯
│╭ filter ────────────────────────────────────────────────────────────────────╮
││ ▸                                                                           │
│╰────────────────────────────────────────────────────────────────────────────╯
╰─ cont 2/9 · 40MB │ img 31 · 12GB (−7GB) │ vol 8MB · log 1.5MB · cache 690MB ─╯
```

- Весь экран очерчен рамкой; отдельными рамками-«окнами» выделены области
  **items** / **details** (список и детали) и **filter** (строка поиска).
- **Строка состояния** — одна строка на нижней грани внешней рамки, во всю
  ширину экрана (список + детали): контейнеры (up/всего · их размер на диске),
  образы (кол-во · размер · сколько можно освободить), volumes, логи, build
  cache. Обновляется по Ctrl-R / Ctrl-L и после удаления.
- **Вкладки Containers / Images** сверху — переключение ←/→ или Tab; в списке
  показывается только активная вкладка.
- **Образы отсортированы по размеру — самые большие сверху**; размер показан
  сразу после имени образа.
- Справа — информация по элементу под курсором (`docker inspect` через `jq`,
  устойчиво к отсутствующим полям; env, хвост логов / история слоёв).
- Диалоги удаления рисуются через `whiptail`/`dialog` (если установлены) —
  настоящие текстовые окна с рамкой; иначе — свой fallback по центру экрана.

## Запуск

```bash
./dockview.sh            # обычный запуск
./dockview.sh --no-logs  # без разового сканирования размера логов
```

Поставить в PATH:

```bash
install -m755 dockview.sh ~/.local/bin/dockview
```

## Клавиши

| клавиша  | действие                                              |
|----------|-------------------------------------------------------|
| ↑/↓      | навигация по списку                                   |
| ←/→, Tab | переключить вкладку Containers ⇄ Images               |
| Del      | удалить выбранный контейнер/образ (запрос Yes/No)     |
| Ctrl-R   | обновить список и статистику                          |
| Ctrl-L   | пересканировать размер логов                          |
| Enter    | полный `docker inspect` в pager                       |
| Ctrl-G   | `docker logs -f` выбранного контейнера                |
| Esc      | выход                                                 |
| печать   | fuzzy-фильтр по текущему списку                       |

## Удаление

- **Контейнер.** Запрос подтверждения Yes/No. Если контейнер запущен —
  предупреждение и `docker rm -f` (остановить и удалить).
- **Образ.** Сначала проверка: если образ использует хотя бы один контейнер
  (в любом состоянии) — выводится окно со списком этих контейнеров, удаление
  отменяется. Иначе — запрос Yes/No и `docker rmi`; если Docker всё равно
  отказал (дочерние образы, другие теги) — показывается его сообщение об ошибке.

## Зависимости

- `docker` (доступ к сокету; текущий юзер в группе `docker`)
- `fzf` >= 0.65 (рамки-окна, `transform-border-label`; проверено на 0.74)
- `jq` — для панели details (без него показывается сырой `docker inspect`)
- `whiptail` или `dialog` — опционально, для диалогов удаления
  (без них используется встроенный fallback)
- Для строки «Logs» — образ `alpine` или `busybox` (подтягивается один раз);
  размер логов читается через одноразовый контейнер с `ro`-монтированием
  `DockerRootDir`, потому что `/var/lib/docker` недоступен без root.
